# Сайт регистрации на конференцию

Форма регистрации + загрузка статьи и заявки + автоматическая проверка оформления статьи
по требованиям оргкомитета + отправка анкеты и прошедшей проверку статьи на почту оргкомитета
(Gmail). Никакие данные и файлы никуда в базу не сохраняются — сайт ничего не хранит сам,
всё уходит письмом.

Проверки на ИИ-генерацию текста в этой версии **нет** — по договорённости эта часть делается вручную.

## Что проверяется автоматически

- формат страницы А4, книжная ориентация
- поля 20 мм со всех сторон
- шрифт Times New Roman
- размер шрифта 14 пт
- одинарный межстрочный интервал
- абзацный отступ 1,25 см
- наличие УДК и МРНТИ
- соответствие индекса УДК теме статьи (сверка по открытым таблицам УДК)
- наличие аннотаций на трёх языках и их объём (150–300 слов)
- количество ключевых слов (5–10) на трёх языках
- наличие всех разделов IMRAD (введение, материалы и методы, результаты, обсуждение, заключение, список литературы)
- количество источников в списке литературы (от 10 до 30)
- наличие ссылок на источники в тексте вида [1]
- формат изображений (JPEG)
- соответствие названий файлов требованиям («Заявка Фамилия И.О..docx», «Статья Фамилия И.О. Тема.docx»)

## Что помечается как «требует ручной проверки»

- чёрно-белая цветовая гамма изображений
- расположение подписей к рисункам/таблицам
- отсутствие автонумерации Word
- актуальность источников (5–7 лет) и доля WoS/Scopus (≥30%)
- соответствие списка литературы конкретному стилю (ГОСТ/APA/IEEE и т.п.)

Автоматическая проверка работает с файлами **.docx** (не .doc и не .pdf).

Пункты «требует ручной проверки» (жёлтые) участникам не показываются — их видит
только организатор: полный список (включая жёлтые пункты) приходит в письме на
`konferencia.edu@gmail.com` вместе с файлами. Автору статьи на сайте выводятся
только результаты автоматической проверки — зелёные (✅ соответствует) и красные
(❌ не соответствует).

## Что происходит с присланными файлами

[#что-происходит-с-присланными-файлами](#что-происходит-с-присланными-файлами)

Файлового хранилища на сайте нет — файлы никуда не сохраняются. При отправке формы:

1. Файл статьи и файл заявки автоматически проверяются по требованиям оформления (в памяти
   сервера — на диск ничего не пишется).
2. Автору на указанную им почту всегда уходит письмо с результатом проверки (зелёные/красные пункты).
3. Если статья прошла проверку — организатору на почту `konferencia.edu@gmail.com`
   (адрес задаётся переменной `NOTIFY_EMAIL`, по умолчанию — именно этот) уходит второе письмо
   с данными анкеты и файлами заявки и статьи **вложениями** (.docx), плюс полный список проверок,
   включая пункты «требует ручной проверки».
4. Если статья проверку не прошла — письмо организатору не отправляется, только автору с замечаниями.
5. Данные анкеты (без самих файлов) отдельно записываются новой строкой в **Google Sheets**
   (см. настройку ниже) — чтобы был удобный общий список всех заявок, а не только письма в почте.
   Сами файлы статьи/заявки в таблицу не попадают — только их имена, для истории.

## Google Sheets (список заявок)

[#google-sheets-список-заявок](#google-sheets-список-заявок)

Каждая заявка добавляется новой строкой в вашу таблицу Google Sheets: дата/время, ФИО,
email, организация, город, страна, степень, телефон, тема статьи, секция, статус проверки,
имя файла статьи, имя файла заявки.

Настройка (один раз):

1. Создайте таблицу на https://sheets.google.com — любое название, например «Заявки на конференцию».
   В первой строке (шапка) можно вручную прописать названия столбцов в том же порядке, что выше —
   для красоты, на саму запись это не влияет.
2. Скопируйте **ID таблицы** из её ссылки: `https://docs.google.com/spreadsheets/d/ЭТОТ-КУСОК/edit` —
   это и есть `GOOGLE_SHEET_ID`.
3. Зайдите в [Google Cloud Console](https://console.cloud.google.com/), создайте (или выберите)
   проект, включите **Google Sheets API** (Библиотека API -> найти "Google Sheets API" -> Enable).
4. Создайте сервисный аккаунт: **IAM и администрирование -> Сервисные аккаунты -> Создать сервисный
   аккаунт**. Роль можно не назначать — доступ выдаётся напрямую в таблице (следующий шаг).
5. Откройте созданный сервисный аккаунт -> вкладка **Ключи** -> **Добавить ключ -> Создать ключ ->
   JSON**. Скачается файл — в нём есть поля `client_email` и `private_key`.
6. Откройте вашу таблицу -> кнопка **Настройки доступа** -> добавьте email из `client_email`
   (выглядит как `имя@проект.iam.gserviceaccount.com`) с правом **Редактор**.
7. В переменные окружения добавьте:
   - `GOOGLE_SHEET_ID` — ID таблицы из шага 2.
   - `GOOGLE_SERVICE_ACCOUNT_EMAIL` — значение `client_email` из JSON-файла.
   - `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` — значение `private_key` из JSON-файла целиком
     (вставьте как есть, вместе с `-----BEGIN PRIVATE KEY-----` и переносами строк).
   - `GOOGLE_SHEET_NAME` (необязательно) — название листа внутри таблицы, если не «Заявки»
     (по умолчанию используется лист с названием `Заявки` — либо переименуйте свой лист так,
     либо укажите тут его реальное название, например `Sheet1`).

Если переменные не заданы — запись в таблицу просто пропускается (в логах будет предупреждение),
остальной сайт продолжает работать как обычно.

## Проверка файла заявки

Заявка проверяется по официальному шаблону (таблица «Сведения об авторе(ах)»): проверяется
заполненность всех обязательных полей — ФИО, учёная степень, должность, организация, город/страна,
email (плюс корректность формата email), телефон, название статьи, секция конференции, форма
участия. Поле ORCID необязательное. Если файл не соответствует структуре шаблона (нет таблицы) —
включается упрощённая проверка (файл не пустой) с пометкой на ручную сверку.

## ИИ-ассистент «Арай»

На сайте есть плавающая кнопка чата (правый нижний угол) — ИИ-ассистент по имени **Арай**, отвечает
на вопросы авторов о требованиях к оформлению статьи и заявки, на основе текста требований,
зашитого в `lib/requirements.js`. Использует Gemini API от Google (модель `gemini-2.5-flash`,
бесплатный тариф).

Чтобы это заработало, нужен ключ API:
1. Зайдите на https://aistudio.google.com/apikey, войдите через Google-аккаунт.
2. Нажмите **Create API key**, выберите или создайте проект.
3. Скопируйте появившийся ключ (начинается с `AIza...`).
4. Вставьте ключ в переменную окружения `GEMINI_API_KEY` в Vercel.

Бесплатный тариф Gemini даёт лимит порядка 250–1500 запросов в день в зависимости от модели —
для чат-ассистента конференции этого с большим запасом хватает, карта не требуется.

Если требования изменятся — правьте текст прямо в `lib/requirements.js`, ассистент сразу
начнёт отвечать по новой версии после следующего деплоя.

## Деплой (пошагово)

### 1. Gmail (отправка писем)

1. Включите двухэтапную аутентификацию на аккаунте Google, с которого будете слать письма
   (Аккаунт Google -> Безопасность -> Двухэтапная аутентификация).
2. Создайте пароль приложения: Аккаунт Google -> Безопасность -> Пароли приложений
   (может быть по прямой ссылке https://myaccount.google.com/apppasswords).
   Выберите тип "Почта" / "Другое", придумайте название (например `conference-site`) -> Google выдаст
   16-символьный пароль.
3. `GMAIL_USER` — сам email, с которого будут отправляться письма, например `konferencia.edu@gmail.com`.
4. `GMAIL_APP_PASSWORD` — тот самый 16-символьный пароль приложения (не обычный пароль от Gmail!).
5. `NOTIFY_EMAIL` — куда слать копии прошедших проверку статей вместе с файлами.
   Если переменную не задавать, копии по умолчанию уходят на `konferencia.edu@gmail.com`.

Ограничение Gmail — не более ~500 писем в сутки с одного аккаунта, для конференции этого более чем достаточно.
Учтите также лимит на размер вложений (обычно около 25 МБ на письмо) — для .docx статей этого с большим запасом хватает.

### 2. Деплой на Vercel

1. Загрузите этот проект в свой репозиторий на GitHub.
2. Зайдите на https://vercel.com -> New Project -> импортируйте репозиторий.
3. В настройках проекта (**Environment Variables**) добавьте `GMAIL_USER`, `GMAIL_APP_PASSWORD`,
   `NOTIFY_EMAIL` (опционально), `GEMINI_API_KEY` (для ИИ-ассистента и проверки УДК),
   `GOOGLE_SHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY`
   и `GOOGLE_SHEET_NAME` (опционально) с реальными значениями.
4. Нажмите Deploy. Через пару минут сайт будет доступен по адресу вида `your-project.vercel.app`.
5. При желании подключите свой домен в разделе **Domains**.

### 3. Локальный запуск для проверки перед деплоем

```bash
npm install
cp .env.example .env.local   # и заполнить реальными значениями
npm run dev
```

Сайт откроется на http://localhost:3000

## Что ещё нужно донастроить под себя

- **Форма «Заявка»**: в требованиях упомянута отдельная форма заявки, но её шаблон не был передан —
  сейчас в `app/register/page.js` собран стандартный набор полей (ФИО, степень, организация, город,
  страна, email, телефон). Пришлите точный шаблон формы — поля можно быстро подогнать.
- **Список секций конференции**: сейчас это простое текстовое поле, легко заменить на выпадающий список.
- **Просмотр заявок**: список всех заявок (без файлов) теперь виден прямо в вашей таблице Google
  Sheets, а сами файлы статьи/заявки — во входящих на `konferencia.edu@gmail.com`. Если понадобится
  админ-страница со списком заявок прямо на сайте — тоже можно добавить, но это отдельная задача.
