# Сайт регистрации на конференцию

Форма регистрации + загрузка статьи и заявки + автоматическая проверка оформления статьи
по требованиям оргкомитета + сохранение в базе (Supabase) + email-уведомления (Resend).

Проверки на ИИ-генерацию текста в этой версии **нет** — по договорённости эта часть делается вручную.

## Что проверяется автоматически

- формат страницы А4, книжная ориентация
- поля 20 мм со всех сторон
- шрифт Times New Roman
- размер шрифта 14 пт
- одинарный межстрочный интервал
- абзацный отступ 1,25 см
- наличие УДК и МРНТИ
- наличие аннотаций на трёх языках и их объём (150–300 слов)
- количество ключевых слов (5–10) на трёх языках
- наличие всех разделов IMRAD (введение, материалы и методы, результаты, обсуждение, заключение, список литературы)
- количество источников в списке литературы (не менее 15)
- наличие ссылок на источники в тексте вида [1]
- формат изображений (JPEG)
- соответствие названий файлов требованиям («Заявка Фамилия И.О..docx», «Статья Фамилия И.О. Тема.docx»)

## Что помечается как «требует ручной проверки»

- чёрно-белая цветовая гамма изображений
- расположение подписей к рисункам/таблицам
- отсутствие автонумерации Word
- актуальность источников (5–7 лет) и доля WoS/Scopus (≥30%)
- соответствие списка литературы конкретному стилю (ГОСТ/APA/IEEE и т.п.)

Автоматическая проверка работает с файлами **.docx** (не .doc и не .pdf).

## Проверка файла заявки

Заявка проверяется по официальному шаблону (таблица «Сведения об авторе(ах)»): проверяется
заполненность всех обязательных полей — ФИО, учёная степень, должность, организация, город/страна,
email (плюс корректность формата email), телефон, название статьи, секция конференции, форма
участия. Поле ORCID необязательное. Если файл не соответствует структуре шаблона (нет таблицы) —
включается упрощённая проверка (файл не пустой) с пометкой на ручную сверку.

## ИИ-ассистент «Арай»

На сайте есть плавающая кнопка чата (правый нижний угол) — ИИ-ассистент по имени **Арай**, отвечает
на вопросы авторов о требованиях к оформлению статьи и заявки, на основе текста требований,
зашитого в `lib/requirements.js`. Использует Gemini API от Google (модель `gemini-3.6-flash`,
бесплатный тариф).

Чтобы это заработало, нужен ключ API:
1. Зайдите на https://aistudio.google.com/apikey, войдите через Google-аккаунт.
2. Нажмите **Create API key**, выберите или создайте проект.
3. Скопируйте появившийся ключ (начинается с `AIza...`).
4. Вставьте ключ в переменную окружения `GEMINI_API_KEY` в Vercel.

Бесплатный тариф Gemini даёт лимит порядка 250–1500 запросов в день в зависимости от модели —
для чат-ассистента конференции этого с большим запасом хватает, карта не требуется.

Если требования изменятся — правьте текст прямо в `lib/requirements.js`, ассистент сразу
начнёт отвечать по новой версии после следующего деплоя.

## Деплой (пошагово)

### 1. Supabase (база данных + хранилище файлов)

1. Зарегистрируйтесь на https://supabase.com, создайте новый проект.
2. В разделе **SQL Editor** выполните содержимое файла `supabase/schema.sql` из этого проекта.
3. В разделе **Storage** создайте приватный бакет с именем `papers`.
4. В разделе **Project Settings -> API** скопируйте:
   - `Project URL` -> это `NEXT_PUBLIC_SUPABASE_URL`
   - `service_role` ключ (секретный!) -> это `SUPABASE_SERVICE_ROLE_KEY`

### 2. Gmail (отправка писем)

1. Включите двухэтапную аутентификацию на аккаунте Google, с которого будете слать письма
   (Аккаунт Google -> Безопасность -> Двухэтапная аутентификация).
2. Создайте пароль приложения: Аккаунт Google -> Безопасность -> Пароли приложений
   (может быть по прямой ссылке https://myaccount.google.com/apppasswords).
   Выберите тип "Почта" / "Другое", придумайте название (например `conference-site`) -> Google выдаст
   16-символьный пароль.
3. `GMAIL_USER` — сам email, например `konferencia.edu@gmail.com`.
4. `GMAIL_APP_PASSWORD` — тот самый 16-символьный пароль приложения (не обычный пароль от Gmail!).
5. `NOTIFY_EMAIL` — куда слать копии прошедших проверку статей (можно тот же адрес).

Ограничение Gmail — не более ~500 писем в сутки с одного аккаунта, для конференции этого более чем достаточно.

### 3. Деплой на Vercel

1. Загрузите этот проект в свой репозиторий на GitHub.
2. Зайдите на https://vercel.com -> New Project -> импортируйте репозиторий.
3. В настройках проекта (**Environment Variables**) добавьте все переменные из `.env.example`
   с реальными значениями.
4. Нажмите Deploy. Через пару минут сайт будет доступен по адресу вида `your-project.vercel.app`.
5. При желании подключите свой домен в разделе **Domains**.

### 4. Локальный запуск для проверки перед деплоем

```bash
npm install
cp .env.example .env.local   # и заполнить реальными значениями
npm run dev
```

Сайт откроется на http://localhost:3000
